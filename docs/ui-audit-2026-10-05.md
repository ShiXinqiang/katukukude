# 前端与业务流程补充检查 · 2026-10-05

本记录更新上一轮“没有商品/订单，无法实测”的结论。实际数据操作使用已获授权的管理员与所属商家账号，测试商品明确标注勿购、不销售、不配送。

## 已修复并验证

1. **刷新深色闪白**：原来在首页useEffect才读主题，首次绘制为浅色。改为根布局head内同步脚本，在body绘制前设置主题、color-scheme、画布底色与玻璃参数；设置页同步更新画布。实际切为深黑后刷新，DOM确认theme=dark、画布rgb(5,5,6)、头部初始化脚本存在。脚本单测覆盖深色、浅色、异常值、存储被禁用。
2. **商品无法提交审核**：真实发布触发数据库products_status_check错误；旧约束仅接受draft/active/archived。数据库与幂等schema初始化补齐pending/rejected。修复后实际提交和管理员审核均成功。
3. **结算缺少运费总额**：新增服务端quote接口，使用当前价格/库存、按商家取最大运费、不同商家相加。结算前展示商品、运费、含运费合计；金额核对失败时不能提交。
4. **规格提示残留**：选择规格或成功购买后清理旧错误提示。搜索页首屏先显示加载态，不先报无商品。
5. **旧发布页**：移除无人使用的PublishPage组件、导入和View分支，保留商家后台ProductEditor为唯一商品发布流程。
6. **普通用户入驻接口**：统一前后端介绍长度10–50字；空坐标保持null而非0；审核中禁止重复提交；ON CONFLICT仅允许驳回状态重提，避免并发覆盖审核结果。普通用户权限与申请状态用隔离接口测试验证，尚未完成普通账号的真实表单上传/提交。
7. **手机适配**：增加VisualViewport键盘高度处理、底栏/提交按钮避让、弹窗可视高度限制、触屏输入框16px和小屏按钮间距、安全区。未宣称真机验证。
8. **扫码**：识别后停止摄像头和计时器，避免结果更新再次申请相机；补充无相机、播放失败、图片损坏、剪贴板拒绝提示；原生BarcodeDetector不可用时动态加载jsQR本地识别二维码，不上传画面。依赖固定1.4.0，已提交lockfile。已知二维码像素能成功解码，纯白图片返回无结果。
